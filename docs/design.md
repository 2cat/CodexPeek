# 产品与接入说明

## 显示规则

监控本机 Codex 桌面端的用户会话。内部子代理和工具调用不独立计数；账号额度由同一账号共享，不能当作单个任务的预算。

状态优先级为：断线 → 等待确认 → 等待回复 → 异常 → 运行 → 空闲。

| 条件 | 状态条示例 |
| --- | --- |
| 等待批准操作 | 等待确认 · 1 项 |
| 等待用户输入 | 等待回复 · 1 项 |
| 未处理的失败 | 任务异常 · 1 项 |
| 单任务运行 | 命令 · git status --short；回复 · 正在更新 README |
| 多任务运行 | 正在运行 2 项任务 |
| 没有活跃任务且存在已同步历史 | 上次：任务名称 |
| 没有可用历史 | 暂无运行任务 |
| 连接或协议异常 | 状态未同步 |

等待任务不计入运行数量。动作来自执行事件，不按 CPU、文件变化或时间猜测。命令显示会省略可识别的 PowerShell 启动器，保留实际命令内容；搜索和文件列表命令也显示内容。状态条缩短动作前缀，为摘要留出空间。

回复摘要来自当前公开回复的最新非空行；超过 28 个字符时显示末尾片段，随流式内容更新。工具调用优先显示公开的动作标题，缺少标题时显示具体工具名称。没有可用动作内容时显示任务名称作为上下文；不读取内部推理内容，也不把已完成的命令继续显示为正在执行。

空闲标题取最近开始的那次已结束任务；不建立额外的持久化历史库。展开列表先显示当前需要处理的任务，再单独显示“最近任务”，最多保留 3 个已结束会话。历史任务显示最后公开回复摘要和“最近运行”时间，不继续累加耗时，不计入运行或等待数量。只有历史时，标题显示“最近 3 个任务”等实际数量；完全没有记录时才显示空状态。不虚构百分比进度、结束时间或预计完成时间。

额度选取返回窗口中剩余比例最低的一项，百分比为 `100 - usedPercent`，倒计时来自 `resetsAt` 的 Unix 秒时间戳。窗口长度与实际剩余时间分开处理；缺失值不视为零，旧数据标为未更新。

## 窗口与交互

使用免激活的 WinForms 浮动窗口（`WS_POPUP`）贴在主屏任务栏左侧空白区域。通过 Win32 owner 关系让系统保持入口位于任务栏上方，显示后及任务栏句柄变化时重新关联；不再每 750 毫秒抢占置顶层级。入口为 320 × 40 DIP，按可用空间收窄；不足 180 DIP 时退到托盘。展开面板宽 460 DIP，空闲高度为 184 DIP，有任务时按任务数量展开，最多占可用屏幕高度的 70%。

每 4 秒通过 UI Automation 读取任务栏按钮位置。开始菜单打开时，按钮列表可能暂时为空或读取异常；任务栏句柄、边界和 DPI 都没变化时，保留上次可靠的入口位置。首次启动还没读到按钮、任务栏上下文变化或新测量确认空间不足时，退到托盘，不推测空位。每次测量完成都会更新完成时间；测量挂起超过 12 秒仍隐藏入口。

入口的小圆点仅表示状态：蓝色运行、黄色等待确认或回复、红色异常、灰色空闲或未同步，不表示额度、进度或重置次数。接口没有提供历史重置次数，当前没有新增重置计数。

入口和面板通过 DWM 使用原生圆角、边框及 Acrylic；保留原生 frame 并移除标题栏，不使用整窗 Opacity，避免文字跟着变淡。正常材质路径不设置窗口 Region；材质不可用时入口回退到实色圆角。[DWMSBT_TRANSIENTWINDOW](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type) 使用系统 Desktop Acrylic，但不保证与任务栏按钮使用完全相同的材质参数。

深色底层原先 alpha 为入口 155 / 悬停 180、面板 195，遮盖过重。本次减为 70 / 100 / 85，并略提亮次要文字；这些数值是额外底色的 alpha，不是系统 Acrylic 的总不透明度。较亮背景下的文字可读性仍需实机检查。关闭系统透明效果或启用高对比度时，启动时使用实色背景；不支持系统材质时也使用实色背景。

入口的两行字号为 13 / 11 DIP。任务卡片高 124 DIP、间隔 8 DIP、圆角 8 DIP；标题、执行详情、最近进展和计时字号为 14 / 13 / 12 / 11 DIP。整个卡片可点击，键盘焦点显示圆角蓝色描边。列表独立绘制玻璃底层，避免透明 Panel 重画父窗口产生间隙条带。卡片随实际滚动区域收窄，数据更新和任务增删完成布局后恢复滚动位置。空闲面板省略零任务计数，连接信息简化为“已连接”。

点击展开、Escape / 失焦收起，点击任务通过 `codex://threads/<id>` 打开原会话。批准操作和回复用户问题始终在 Codex 中完成。首版没有机器人、自动审批、远程设备汇总或开机自启。

## 数据流

1. `App.cs` 启动 Node 子进程，通过标准输出接收一行一个 JSON 状态。
2. `backend.mjs` 只读查询 `%USERPROFILE%\.codex\state_5.sqlite`，发现未归档的本机桌面用户会话，每 4 秒检查一次目录。
3. 通过 `\\.\pipe\codex-ipc` 订阅桌面会话状态。每帧为 4 字节小端长度加 JSON，当前处理状态协议版本 11。
4. `TaskFeed` 处理快照与增量修订，`present` 生成状态条及任务列表。修订丢失时重新订阅，断线时清空运行状态并重连。
5. 每 60 秒启动 npm Codex CLI 的 App Server，通过 `account/rateLimits/read` 读取额度，再结束该查询进程。此请求不运行模型任务。
6. 每 5 秒重新输出视图以更新倒计时。窗口退出时关闭数据组件的标准输入，数据组件释放连接并退出。

Desktop IPC 不会提供所有旧会话的快照。历史记录补充读取 SQLite 中最近候选的 `rollout_path`，限定在当前 Codex 目录的会话文件中，只读有限大小的尾部。仅接受最新生命周期事件明确为结束或停止的记录；后续存在未结束的开始事件就排除。已有 IPC 状态覆盖相同会话，防止正在运行的任务出现在历史中。单条历史文件读取失败不影响实时状态。

没有本地 HTTP 服务，不直接读取认证文件，也不新增任务正文存储。执行记录只取公开结束事件及最后公开回复，不读取内部推理内容。命令和任务进展只在进程内用于显示。`npm start` 是约 12 秒的数据诊断入口，会把状态 JSON 输出到终端，其中可能含任务内容，不能直接当作公开日志上传。

测试可通过 `CODEX_HOME` 和 `CODEX_PEEK_PIPE` 指向隔离的数据库和命名管道。生产环境仍使用本机默认位置。

## 维护边界

内部桌面协议、会话数据库及 CLI 安装结构都可能变化。协议不兼容时应明确显示错误，不能退回猜测运行状态。官方 App Server 用于本工具的额度请求，另起一个 App Server 不等于能够观察已有桌面会话。

功能测试边界沿用：执行事件 → 任务状态；任务和额度 → 展示文案；原生窗口 → 定位和操作结果。接口、布局与实际最终启动方式分别验证。
